# מערכת זמינות כוח אדם

דשבורד זמינות לעובדי אבטחה (אחמ"ש / מאבטח / שומר) – חופשות, מחלות, מילואים, סטודנטים ותקן מינימלי.
האתר רץ על GitHub Pages, והנתונים נשמרים ב-Supabase (מסד נתונים Postgres חינמי בענן).

## קבצים
| קובץ | מה זה |
|---|---|
| `index.html` | כל האפליקציה |
| `schema.sql` | הקמת הטבלאות וההרשאות ב-Supabase (מריצים פעם אחת) |

## הקמה (כ-10 דקות, חד-פעמי)

1. **פרויקט Supabase** – נרשמים ב-supabase.com ← New project. אזור מומלץ: Frankfurt (eu-central-1). שומרים את סיסמת המסד במקום בטוח.
2. **טבלאות** – SQL Editor ← New query ← מדביקים את כל `schema.sql` ← Run.
3. **משתמש מנהל** – Authentication ← Users ← Add user ← Create new user. אימייל + סיסמה, ומסמנים Auto Confirm User.
4. **לחסום הרשמה עצמית** – Authentication ← Sign In / Providers ← מכבים את *Allow new users to sign up*. כך רק משתמשים שאתה יוצר יכולים להיכנס.
5. **מפתחות** – Project Settings ← API (או API Keys). מעתיקים:
   - Project URL ← לתוך `SUPABASE_URL` ב-`index.html`
   - anon / publishable key ← לתוך `SUPABASE_ANON_KEY`
   
   ⚠️ **לא** להשתמש ב-`service_role` / secret key – הוא עוקף את כל ההרשאות ואסור שיופיע באתר.
6. **GitHub Pages** – מעלים את `index.html` לריפו ← Settings ← Pages ← Branch `main`, תיקייה `/ (root)` ← Save.

## אבטחה
- ה-anon key גלוי בקוד וזה תקין: בלי התחברות, מסד הנתונים לא מחזיר ולא מקבל כלום (Row Level Security).
- כל משתמש מחובר יכול לקרוא ולערוך הכל. לא ליצור משתמשים למי שלא אמור לערוך.

## הערות
- אם יש נתונים ישנים ששמורים בדפדפן ומסד הנתונים ריק, המערכת תציע להעלות אותם בכניסה הראשונה.
- שינוי ממכשיר אחד מופיע בשאר המכשירים הפתוחים תוך שניה (Realtime).
- פרויקט Supabase חינמי מושהה אחרי שבוע בלי שום פעילות. נכנסים לאתר פעם בכמה ימים, או לוחצים Restore בלוח הבקרה של Supabase. הנתונים לא נמחקים.
- גיבוי: הגדרות ← ייצוא גיבוי (JSON). מומלץ פעם בחודש.
- בלי מפתחות (שני הערכים ריקים) המערכת עובדת במצב מקומי ושומרת רק בדפדפן.
